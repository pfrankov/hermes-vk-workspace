# Changelog

## 0.2.1 — 2026-10-25

### Исправлено

- Мастер настройки проверяет возможность записи всех credentials до изменения YAML. Явный список пользователей отключает allow-all перед сохранением токена, а существующий `extra.base_url` обновляется без конфликтующего поля верхнего уровня.
- Мастер отклоняет токен и ID пользователей с не-ASCII символами до любых изменений: Hermes вырезает такие символы из `.env` и сохранил бы другое значение. При закреплённых администратором ключах мастер называет конкретный ключ, а allow-all отключается первым, чтобы прерванное сохранение не оставляло бота открытым.
- После настройки штатное меню Hermes корректно определяет готовность платформы по настройкам активного профиля и показывает дальнейшие шаги запуска gateway.
- Если сохранённый блок платформы повреждён (например, `home_channel` без корректной платформы), прямой вызов status-hook возвращает «not configured» вместо исключения. Само меню Hermes уже перехватывало такую ошибку.


### Совместимость

- Требуется Hermes **v0.22.5** или новее; CI проверяет стабильный коммит `bf0203a794a07aac3ff764972ab9087baa4e4f4e`. Перед обновлением плагина обновите Hermes штатным способом. Плагин не обновляет установленный host самостоятельно.
- Проверочное окружение собирается через штатный package manager Hermes с его lockfile, включая upstream override Pillow. Сырые `uv pip install` / `uv pip check` не учитывают этот контракт.

### Security

- Прямая зависимость `aiohttp` обновлена **3.14.3 → 3.14.5**: [GHSA-9xw5-w5jj-pvcg](https://github.com/aio-libs/aiohttp/security/advisories/GHSA-9xw5-w5jj-pvcg), [GHSA-2g87-pp6c-29x5](https://github.com/aio-libs/aiohttp/security/advisories/GHSA-2g87-pp6c-29x5), [GHSA-5wr8-gcqf-gqf3](https://github.com/aio-libs/aiohttp/security/advisories/GHSA-5wr8-gcqf-gqf3). Они описывают расход ресурсов при обработке недоверенных HTTP-запросов. Плагин работает исходящим клиентом, не открывает HTTP-сервер; обновление профилактическое и согласует зависимость с поддерживаемым Hermes.
- Проверенный host использует **Pillow 13.0.0 вместо 12.3.0**: [GHSA-5xm2-6676-qcp9](https://github.com/python-pillow/Pillow/security/advisories/GHSA-5xm2-6676-qcp9) позволяет специально подготовленному APNG вызвать большой расход памяти при открытии изображения. Медиа разрешённых пользователей может попадать в обработку изображений Hermes; одного лимита размера загружаемого файла недостаточно. Исправление принадлежит Hermes, поэтому требуется обновление host, а не только плагина.
- Это не утверждение об отсутствии уязвимостей во всех extras Hermes: `messaging` по-прежнему содержит `brotlicffi 1.2.0.2`. Транспорт этого плагина отключает автоматическую декомпрессию, отклоняет Brotli и ограничивает gzip/deflate; другие компоненты host оцениваются отдельно.

## 0.2.0 — 2026-10-20

### Улучшено

- Добавлен нативный мастер настройки `hermes gateway setup`: сервер, токен и список допущенных пользователей, с сохранением остальных настроек и проверкой фактически применённого адреса перед записью секрета.
- Меню выбора сразу показывает страницу с текущим параметром или моделью, включая выбранного провайдера.
- Уже открытые кнопки перестают выполнять команды сразу после остановки gateway, даже когда обработчик ожидает подтверждения от VK.
- Заблокированная или некорректная отправка не читает локальные файлы, не скачивает изображения и не конвертирует звук. Polling не создаёт busy loop на повторяющихся обработанных событиях.
- Добавлены регрессионные тесты настроек, меню, жизненного цикла, медиа и polling. Новых зависимостей нет.


## 0.1.1 — 2026-10-20

### Исправлено

- Проверка доверенных origin использует тот же URL-парсер, что и HTTP-клиент. Международные домены больше не могут пройти проверку под другим ASCII-именем; эквивалентные записи IPv6 распознаются одинаково.

### Изменено

- Цикломатическая сложность ограничена 10 на функцию правилом Ruff C901 в CI. Упрощены разбор событий, объединение правок, обработка вложений, валидация кнопок и HTML-форматирование.
- Убраны неиспользуемые поле настроек и аргумент метода. Вложения дедуплицируются одной структурой, переходы HTML-тегов вычисляются один раз на текстовый сегмент. Преобразование аудио размещено вместе с остальной обработкой медиа.
- Тесты адаптера и меню используют общую фикстуру настоящего адаптера и API mock с проверкой сигнатур. Удалён отдельный тестовый адаптер с дублирующими методами; ожидаемое содержимое форматированных сообщений задано независимо от реализации.
- Добавлены регрессии для IDNA и IPv6, схемы кнопок и точных границ HTML, экранирования и UTF-16. Повторно сверены все 11 методов Bot API с официальными SDK.
- `yarl`, уже устанавливаемый с `aiohttp`, объявлен прямой закреплённой зависимостью. Добавлены правила упрощения кода, порядок подачи в каталог Hermes и описание доступа к данным.

## 0.1.0 — 2026-10-20

Первый выпуск платформы VK Workspace / VK Teams для Hermes Agent v0.22.2.

### Добавлено

- Нативная регистрация платформы и установка через plugin manager Hermes.
- Long polling с атомарным cursor, ограниченным dedup-кешем, backoff и блокировкой единственного потребителя токена.
- Личные чаты, группы, каналы и нативные дочерние чаты обсуждений.
- Авторизация Hermes до загрузки медиа, настройка разрешённых чатов и проверка прямых упоминаний.
- Сохранение цитат и пересылок как контекста без исполнения вложенных команд.
- Потоковые ответы, безопасное форматирование Markdown, длинные сообщения и подписи.
- Приём и отправка файлов, изображений, видео и аудио; голосовые сообщения с распознаванием контейнера и конвертацией TTS через ffmpeg.
- Ограничения origin, переадресаций, HTTP-ответов и размеров файлов; безопасные диагностические сообщения.
- Отказ от скрытого повтора мутаций API и автоматического продолжения при неопределённой доставке.
- Одноразовые меню выбора провайдера, модели и стандартных параметров Hermes с проверкой пользователя, чата, сообщения и сессии.
- Изолированная отправка для cron и `hermes send`, поддержка профилей Hermes.
- Тесты HTTP-контракта и границ безопасности, проверки на настоящем Hermes, CI и правила code review.

### Границы первой версии

- Поддерживается актуальный контракт Hermes; совместимость со старыми версиями не реализуется.
- Cursor подтверждает приём gateway. Отдельной долговечной очереди и гарантии exactly-once нет.
- Подтверждения инструментов и уточняющие вопросы используют штатный текстовый протокол Hermes.
- Проверки не требуют рабочего токена и не считаются испытанием на живом сервере VK Teams.

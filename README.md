# Hermes Agent — VK Workspace

[![CI](https://github.com/pfrankov/hermes-vk-workspace/actions/workflows/ci.yml/badge.svg)](https://github.com/pfrankov/hermes-vk-workspace/actions/workflows/ci.yml)

Платформа [Hermes Agent](https://github.com/NousResearch/hermes-agent) для корпоративного **VK Workspace / VK Teams**. Получает сообщения через long polling: публичный webhook и входящий порт не нужны.

Поддерживает личные и групповые чаты, ветки обсуждений, упоминания, цитаты, файлы, изображения, голосовые сообщения, потоковые ответы и кнопки выбора модели. Авторизация, pairing, команды, сессии, очередь запросов и выполнение агента принадлежат Hermes.

## Требования

- **Hermes Agent v0.22.5** — последний стабильный релиз на 25 октября 2026 года. Проверки используют точный [коммит `bf0203a`](https://github.com/NousResearch/hermes-agent/tree/bf0203a794a07aac3ff764972ab9087baa4e4f4e). Невыпущенные изменения ветки `main` и старые версии Hermes не поддерживаются.
- **Python 3.14**; CI проверяет Python 3.14.10. Используйте окружение актуальной установки Hermes.
- URL Bot API и токен бота вашего сервера VK Teams. Адрес API может отличаться от адреса веб-клиента; уточните его у администратора.
- Настроенный в Hermes агент и провайдер модели. Для распознавания речи нужен настроенный STT в Hermes. Для отправки TTS в MP3/WAV/WebM/FLAC как нативного голосового сообщения нужен `ffmpeg`.

Плагин использует `aiohttp`, его URL-парсер `yarl` и уже используемый Hermes пакет `Markdown`. `yarl` закреплён явно, чтобы проверка доверенных адресов и HTTP-клиент одинаково понимали международные домены и IPv6. Синхронный VK SDK, отдельный сервер, база данных и дополнительный агент не требуются. Манифест допускает Hermes `>=0.22.5`; совместимость с последующими релизами подтверждается обновлением закреплённого host в CI.

Перед обновлением плагина с 0.2.0 обновите Hermes до v0.22.5 штатным способом. Это требуется для исправлений обработки изображений в host; установка плагина не обновляет Hermes. Подробнее — раздел Security в [CHANGELOG.md](CHANGELOG.md).

## Быстрый старт

1. Создайте бота через Metabot вашего VK Teams и получите токен.

2. Установите и включите платформу:

   ```bash
   hermes plugins install pfrankov/hermes-vk-workspace --yes-deps --enable
   ```

   `--yes-deps` подтверждает установку объявленных Python-зависимостей. Для установки проверенного коммита добавьте `--ref` с его полным 40-символьным SHA. Имя плагина — `vk-workspace-platform`; имя платформы — `vk-workspace`.

3. Рекомендуется настроить платформу штатным мастером (сервер, токен и пользователи):

   ```bash
   hermes gateway setup
   ```

   Выберите **VK Workspace**. Мастер сохраняет настройки текущего профиля, не перезаписывает посторонние разделы и не записывает новый токен, пока фактический адрес сервера не совпадёт с указанным. Пустой список пользователей сохраняет прежние правила или стандартный pairing; открытый доступ автоматически не включается. Явный список пользователей сохраняется в `VK_WORKSPACE_ALLOWED_USERS` и одновременно записывает `VK_WORKSPACE_ALLOW_ALL_USERS=false`, поэтому ранее открытый бот закрывается; пользователи, уже одобренные через pairing Hermes, сохраняют доступ. Если токен или правила доступа закреплены администратором, мастер называет такой ключ и ничего не меняет. Токен и ID пользователей в мастере принимаются только в ASCII.

   **При ручной настройке** в `.env` активного профиля Hermes добавьте токен:

   ```dotenv
   VK_WORKSPACE_BOT_TOKEN=YOUR_BOT_TOKEN
   ```

   Для профиля по умолчанию это `~/.hermes/.env`. `YOUR_BOT_TOKEN` — плейсхолдер. Храните файл вне Git и ограничьте доступ к нему. Секреты читаются через механизм профилей Hermes; переменные чужого профиля не подхватываются.

4. При ручной настройке добавьте в существующий `config.yaml` профиль платформы. Сохраните остальные настройки Hermes:

   ```yaml
   platforms:
     vk-workspace:
       enabled: true
       base_url: https://teams.example.com/bot/v1
       allowed_users:
         - alice@example.com
   ```

   Замените домен и пользовательский ID. Идентификатор — точное значение `userId` Bot API, включая домен и другие символы. Поведение платформы задаётся в YAML, токен — в хранилище секретов Hermes.

5. Запустите gateway и напишите боту:

   ```bash
   hermes gateway run
   ```

   Для уже установленной фоновой службы используйте `hermes gateway restart`, затем `hermes gateway status`. Проверяйте текст, ответ на сообщение, входящее вложение и отправку файла: успешный запрос идентификации бота сам по себе не проверяет CDN, STT и права в группах.

## Авторизация и группы

Доступ пользователей проверяет Hermes. `allowed_users` в YAML или `VK_WORKSPACE_ALLOWED_USERS` в `.env` задают список полных пользовательских ID. Непустой список из переменной окружения имеет приоритет перед `allowed_users` в YAML. Можно использовать стандартные настройки Hermes `allow_from` и `group_allow_from` для отдельных списков отправителей.

Без разрешения пользователя платформа не скачивает его файлы. Неавторизованное личное сообщение передаётся стандартному механизму Hermes, который решает, предложить pairing, проигнорировать запрос или отклонить его. Поведение можно задать через `unauthorized_dm_behavior` в настройках платформы. При pairing одобрите запрос штатной командой Hermes и отправьте сообщение повторно; исходное вложение до одобрения не загружается.

Группы и каналы по умолчанию отключены. Разрешите **чат и отправителей**:

```yaml
platforms:
  vk-workspace:
    enabled: true
    base_url: https://teams.example.com/bot/v1
    allowed_users:
      - alice@example.com
    group_allow_from:
      - alice@example.com
      - bob@example.com
    allowed_chats:
      - "123456@chat.agent"
    require_mention: true
```

`allowed_chats` содержит точные `chatId`, без шаблонов. При `require_mention: true` бот реагирует на прямое нативное упоминание, `@[userId_бота]` в тексте или ответ на собственное сообщение. Упоминания внутри пересылки или цитаты не вызывают агента. Чтобы отвечать на все сообщения разрешённых участников разрешённого чата, задайте `require_mention: false`.

Явное открытие доступа всем пользователям возможно через штатный `VK_WORKSPACE_ALLOW_ALL_USERS=true` или `allowed_users: ["*"]`. Оно не отменяет `allowed_chats` и проверку упоминания. YAML-поле `allow_all_users` отклоняется: текущий Hermes его не читает. Применяемые администратором общие правила Hermes также остаются в силе.

### Ветки обсуждений

VK передаёт ветку как собственный дочерний чат и добавляет `parent_topic`. Плагин сохраняет этот дочерний `chatId` как адрес доставки и идентификатор ветки; разрешение группы проверяется по родительскому чату. Ответы приходят в исходную ветку. Для прямой отправки указывайте ID дочернего чата.

Разделение сессий определяется текущим Hermes: стандартные правила для личных чатов, групп, веток и профилей не заменяются собственной таблицей сессий плагина. Общую сессию группы или отдельные сессии участников настраивайте средствами Hermes.

### Несколько ботов

Используйте отдельные профили Hermes с собственными `base_url`, токенами и политиками. Команды настройки можно выполнять с `hermes --profile work …`. Плагин поддерживает профильный gateway и multiplex-контекст Hermes; токен отсутствующего профиля не заменяется токеном профиля по умолчанию.

У одного токена должен быть **один потребитель событий**. Машинная блокировка Hermes предотвращает конкурирующие экземпляры этой платформы. Остановите OpenClaw или другой poller, использующий тот же токен; блокировка не координирует чужие приложения и другие серверы.

## Сообщения и возможности

| Возможность | Поведение |
|---|---|
| Текст и команды | Обычные сообщения и команды обрабатываются Hermes, включая `/new`, `/reset` и `/model` |
| Потоковый ответ | Штатный stream consumer Hermes: отправка, редактирование и завершение сообщения |
| Длинный ответ | Разбиение после HTML-экранирования; теги закрываются в каждом фрагменте |
| Форматирование | Markdown преобразуется в ограниченный HTML: выделение, код, блоки кода, ссылки, списки и читаемое текстовое представление таблиц |
| Цитаты и пересылки | Прямой ответ сохраняет сведения о цитируемом сообщении; пересылки становятся контекстом и не исполняются как команды |
| Кнопки | Выбор провайдера, модели и стандартные choice-меню Hermes; открытие на текущем значении, страницы, возврат и отмена |
| Подтверждение инструментов | Штатный текстовый протокол Hermes; кнопки выбора модели не разрешают выполнение команд |
| Уточняющие вопросы | Штатные текстовые варианты и ответы Hermes |
| Входящие вложения | Файлы, изображения, видео, аудио и стикеры передаются как локальные файлы в стандартный media pipeline Hermes |
| Входящие голосовые | Определение контейнера по байтам; транскрипцию выполняет STT Hermes |
| Отправка вложений | Файлы, изображения и видео через `sendFile`; поддерживаются длинные подписи отдельным сообщением |
| Нативные голосовые | AAC, OGG и M4A; поддерживаемые ненативные контейнеры конвертируются через `ffmpeg` |
| Индикация набора | Нативный `typing`, включая очистку состояния после обработки |
| Редактирование и удаление | Только сообщения, отправленные и учтённые этим экземпляром адаптера |
| Расписание и CLI | Отдельная отправка без gateway/polling через зарегистрированный `standalone_sender_fn` |

Кнопка действует 15 минут, привязана к исходному пользователю, боту, чату, сообщению и сессии. После выбора все кнопки страницы обезвреживаются. Повторное нажатие, другой участник, истёкшее меню и отозванный доступ не меняют состояние Hermes. После перезапуска вызовите команду меню заново.

Платформа не добавляет агенту отдельный инструмент произвольной рассылки, управления участниками или обхода подтверждений. Используются текущие публичные возможности Hermes. История чата не запрашивается; правка ещё не переданного сообщения учитывается только в той же полученной пачке событий. Уже запущенный запрос не переисполняется из-за редактирования сообщения.

## Файлы, сеть и лимиты

Ссылки из `files/getInfo` скачиваются только с доверенных origin. По умолчанию разрешён origin Bot API. Если сервер отдаёт файлы с отдельного CDN, добавьте его явно:

```yaml
platforms:
  vk-workspace:
    enabled: true
    base_url: https://teams.example.com/proxy/bot/v1
    allowed_users: [alice@example.com]
    media_allowed_origins:
      - https://files.example.com
    media_max_mb: 20
```

Origin включает схему, домен и порт; пути и wildcard запрещены. Каждая переадресация проверяется заново, допускается не более трёх переходов. Плагин не добавляет токен бота, cookies или заголовки авторизации к скачиванию. Подписанные URL не передаются модели и не записываются в ошибки.

Для внешних изображений, созданных агентом, используется штатная защита Hermes от SSRF и проверка изображений. На этапе скачивания действуют лимиты host; перед отправкой дополнительно проверяется `media_max_mb` плагина. Локальные файлы проходят штатную проверку путей Hermes и ограниченное чтение обычного файла. Для более строгой политики используйте настройки доставки файлов самого Hermes.

`base_url` принимает адрес сервера или полный путь `/bot/v1`; префикс reverse proxy сохраняется. Нужен HTTPS с доверенным сертификатом. Для внутреннего CA настройте доверие в окружении Python. `allow_insecure_http: true` явно разрешает HTTP; при этом токен передаётся без шифрования. Проверка TLS не отключается. Токен по контракту VK находится в query: журналы reverse proxy должны скрывать параметр `token`.

| Настройка | По умолчанию | Допустимые значения |
|---|---:|---|
| `base_url` | Обязательная | HTTPS URL Bot API |
| `allowed_chats` | `[]` | Точные ID разрешённых групп/каналов |
| `require_mention` | `true` | YAML boolean |
| `poll_time` | `30` | Целое число 1–60 секунд |
| `request_timeout` | `30` | 1–300 секунд; для long poll добавляется `poll_time` |
| `media_max_mb` | `20` | Целое число 1–100 MiB |
| `media_max_bytes` | 20 MiB | Альтернатива `media_max_mb`, 1–104857600 байт |
| `media_allowed_origins` | Origin API | Дополнительные точные доверенные origin |
| `allow_insecure_http` | `false` | Явное разрешение HTTP |

Консервативные локальные пределы: 4096 UTF-16 единиц на отправляемый HTML-фрагмент, 1024 на подпись файла, 128 KiB входящего текста, 10 вложений и 100 частей сообщения, 8 MiB ответа API. Они ограничивают ресурсы плагина и не объявляются универсальными лимитами всех установок VK Teams. Слишком большой или некорректный вход отбрасывается. Неудачная загрузка разрешённого вложения отмечается в контексте сообщения.

## Расписание и прямая отправка

Чтобы задать чат для уведомлений по умолчанию, добавьте в `.env` активного профиля:

```dotenv
VK_WORKSPACE_HOME_CHANNEL=123456@chat.agent
VK_WORKSPACE_HOME_CHANNEL_NAME=Уведомления
```

Отправка в конкретный чат:

```bash
hermes send --to 'vk-workspace:123456@chat.agent' 'Проверка завершена'
hermes send --to 'vk-workspace:123456@chat.agent' 'MEDIA:/absolute/path/report.pdf'
```

`hermes send` и cron используют те же настройки платформы и секреты профиля. Отправитель не забирает события, не изменяет polling cursor и не захватывает блокировку работающего бота. Для ветки передавайте её собственный `chatId`. Ошибка отправки возвращается вызывающему Hermes.

## Доставка и перезапуск

Плагин сохраняет polling cursor атомарно в `state/vk-workspace/` активного профиля Hermes. Имя файла зависит от хеша сервера и токена; сам токен и тексты сообщений там не хранятся. Первая пачка событий обрабатывается, повторные события отсеиваются. Повреждённое состояние вызывает явную ошибку; cursor не сбрасывается автоматически.

**Cursor подтверждает приём сообщения gateway, а не окончание работы агента или доставку ответа.** Здесь нет отдельной долговечной очереди входящих сообщений. При аварии между передачей события Hermes и завершением ответа сообщение может остаться без ответа; после проверки состояния отправьте запрос заново. Повтор запроса может повторить уже выполненные агентом действия. Удаление cursor может привести к повторному получению событий, поэтому сначала остановите gateway и сохраните копию состояния.

VK не предоставляет используемому API гарантию идемпотентности отправки. Плагин не повторяет сообщение после таймаута, обрыва соединения или неоднозначного ответа сервера. HTTP-клиенту также запрещён скрытый повтор GET-запроса. Если часть длинного ответа уже отправлена, повтор всей операции не выполняется. При неизвестном результате блокируется автоматическое продолжение текущего ответа; следующий пользовательский запрос получает отдельный контекст доставки. Подтверждённый HTTP 429 может быть повторён Hermes, если до него не было отправленных фрагментов.

## Обновление и диагностика

```bash
hermes plugins update vk-workspace-platform
hermes plugins list
hermes gateway restart
hermes gateway status
```

После обновления нужен перезапуск gateway. Если он не запущен как служба, остановите процесс и снова выполните `hermes gateway run`.

| Симптом | Что проверить |
|---|---|
| Платформа не загружается | Версию Hermes/Python, включение плагина, зависимости и `base_url` |
| Не проходит `self/get` | Токен активного профиля, URL Bot API, сертификат и доступность сервера |
| Бот молчит в группе | `allowed_chats`, авторизацию отправителя, упоминание и права бота |
| Текст работает, файлы нет | Origin CDN в `media_allowed_origins`, размер и права на получение файла |
| Нет транскрипции | Настройку и работоспособность STT в Hermes |
| Не отправляется TTS | Формат исходного аудио, наличие `ffmpeg` и лимит файла |
| Кнопка не действует | Кто вызвал меню, срок действия, действующий доступ; повторите `/model` |
| Ошибка блокировки | Второй gateway/profile или приложение с тем же токеном |
| Ошибка cursor | Сохраните копию состояния и выясните причину; не удаляйте файл на работающем gateway |

Платформе требуется обычная загрузка плагинов в процессе gateway. Режим изолированного plugin host текущего Hermes не переносит живые объекты адаптеров между процессами.

## Разработка и проверка

Hermes загружает код из каталога плагина; `pyproject.toml` — виртуальный проект uv с закреплёнными зависимостями. Такой формат позволяет установить платформу в нескольких профилях без конфликта имён в общем окружении Hermes.

```bash
git clone https://github.com/pfrankov/hermes-vk-workspace.git
cd hermes-vk-workspace
git clone https://github.com/NousResearch/hermes-agent.git .ci/hermes-agent
git -C .ci/hermes-agent checkout bf0203a794a07aac3ff764972ab9087baa4e4f4e
export HERMES_SOURCE_PATH="$PWD/.ci/hermes-agent"
uv python install 3.14.10
bash scripts/build-test-env.sh
uv run --no-sync ruff check .
uv run --no-sync ruff format --check .
uv run --no-sync pytest
```

Для этого рецепта нужен uv 0.13.6 или новее: более ранние версии не содержат Python 3.14.10 в каталоге загрузок. Обновление проверочного окружения не обновляет Python рабочей установки Hermes.

Скрипт создаёт новое одноразовое `.venv` и отказывается перезаписывать существующее. Он отдельно проверяет lockfile плагина, затем штатным PM собирает и проверяет граф `messaging` + `dev` из lockfile host с upstream overrides. Прямые зависимости плагина и инструменты совпадают с этим графом; транзитивные версии берутся из host, а не из искусственного объединения двух lockfile. Это рецепт только для тестов, не способ менять рабочую установку Hermes. После установки host используйте `--no-sync`: точная синхронизация только зависимостей плагина удалит отдельно установленный Hermes. Тесты используют отдельные временные профили, настоящий host и локальные HTTP-серверы. Они проверяют контракт API, границы доступа и файлов, cursor, отмену, потоковую доставку и кнопки. Живой корпоративный бот для CI не нужен; эти проверки не заменяют приёмочный тест на конкретном сервере VK.

Ruff проверяет цикломатическую сложность McCabe: не более 10 на функцию, включая тесты. Код разделён по обязанностям: регистрация, настройки, HTTP API, события, состояние, адаптер Hermes, меню, медиа и форматирование. Общая фикстура тестов использует настоящий адаптер; mock заменяет только удалённый API и проверяет сигнатуры его методов. Отдельные функции с одним вызовом допустимы для контрактов host, callback, проверок входных данных и управления ресурсами; одноразовая обвязка остаётся на месте использования.

Правила изменений и code review находятся в [AGENTS.md](AGENTS.md), история — в [CHANGELOG.md](CHANGELOG.md). CI проверяет каждый PR. Автоматическое Codex Review включается отдельно для репозитория в [настройках ChatGPT](https://chatgpt.com/settings/code-review); наличие workflow и AGENTS само по себе его не включает.

### Публикация в каталоге Hermes

Каталог пополняется через PR владельца или основного участника проекта в `NousResearch/hermes-agent`. В PR добавляется файл `plugin-catalog/vk-workspace-platform.yaml`: `tier: community`, `category: platform`, URL этого репозитория, версия из `plugin.yaml` и полный 40-символьный SHA проверенного коммита. SHA определяет устанавливаемый код; для обновления нужен отдельный PR с новым SHA. Публикация в PyPI не требуется.

Перед отправкой выполните в актуальном checkout Hermes:

```bash
hermes plugins validate /path/to/hermes-vk-workspace --install-deps
python3 scripts/validate_plugin_catalog.py plugin-catalog/vk-workspace-platform.yaml
```

Карточка заявляет единственную обязательную переменную `VK_WORKSPACE_BOT_TOKEN` и пустые списки `provides_tools`, `provides_hooks`, `provides_middleware`. Платформа регистрируется через публичный `register_platform`. В PR опишите возможности и доступ к данным; для меню приложите снимок экрана. CI каталога проверяет закреплённый коммит на Hermes из самого PR, а сопровождающий принимает решение о включении. Точные поля и правила находятся в [официальной инструкции](https://hermes-agent.nousresearch.com/docs/developer-guide/plugins/catalog-submission).

### Доступ к данным и фоновая работа

Пока работает gateway, плагин поддерживает исходящий long polling к заданному оператором Bot API. Токен передаётся параметром query. Разрешённые сообщения и вложения поступают в обычные процессы агента, обработки медиа и распознавания речи Hermes; дальнейшая передача провайдерам определяется настройками Hermes.

Плагин скачивает вложения с доверенных origin в кеш Hermes и читает локальные файлы, разрешённые механизмом доставки Hermes. Для преобразования голосовых сообщений штатный помощник Hermes может запускать локальный `ffmpeg`. На диске сохраняется cursor в каталоге состояния активного профиля; для исключения второго poller используется блокировка по хешу сервера и токена. Секретами управляет Hermes. Собственного хранилища токенов, телеметрии и механизма замены собственного кода у плагина нет.
